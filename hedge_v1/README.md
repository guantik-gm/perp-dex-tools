# Hedge V1 对冲交易模块

## 模块概述

hedge_v1 是基于原有 hedge 对冲模式的重构优化版本，通过策略化架构设计实现了多策略组合的对冲交易。在 EdgeX + Lighter 的 0.05 个单位 BTC 场景下，能够将 EdgeX 单边交易量磨损降至万分之1.5的平均水平（包括 EdgeX 的 VIP1 手续费，不含活动奖励与返佣），相比原版本纯交易磨损可降低50%以上，在某些时段甚至能够实现盈利。

## 模块化重构

### 1. 重构整体程序结构

- **抽象基类设计**: `HedgeBotAbc` 提供通用对冲逻辑和状态管理
- **交易所解耦**: 各交易所独立实现，继承抽象基类
- **Lighter 统一代理**: `LighterProxy` 统一管理 Lighter 交易所接口
- **最大化复用**: 新交易所接入只需实现特定方法，大幅提升扩展性

### 2. 对冲策略模块化

- **策略基类**: `HedgeStrategy` 定义统一的策略接口
- **优先级机制**: 支持开仓/平仓优先级配置
- **策略组合**: 多策略并行执行，支持 TRIGGER/PASS/REJECT 三种决策结果
- **智能决策**: 通过策略组合实现精准的开平仓时机控制

### 3. 监控与通知系统

- **实时监控**: `HedgeMonitor` 提供全方位状态监控
- **详细统计**: 开平仓统计信息、盈亏分析、磨损率计算
- **即时通知**: 支持 Telegram 通知，实时掌握交易状态

## 模块结构

```
hedge_v1/
├── hedge_mode_abc.py          # 抽象基类，通用对冲逻辑
├── hedge_mode_edgex.py        # EdgeX 交易所实现
├── hedge_mode_grvt.py         # GRVT 交易所实现  
├── lighter_proxy.py           # Lighter 交易所统一代理
├── hedge_monitor.py           # 监控与通知管理
└── strategy/                  # 策略模块目录
    ├── hedge_strategy.py      # 策略基类定义
    ├── timing_strategy.py     # 持仓时间控制策略
    ├── spread_strategy.py     # 价差套利策略
    ├── liquid_risk_strategy.py    # 清算风险策略
    └── price_volatility_strategy.py   # 价格波动策略
```

## 默认对冲策略

### 1. 时间策略 (TimingStrategy)

- **优先级**: 20 (中等)
- **功能**: 控制开平仓的时间间隔和持仓时长

**核心参数**:
- `open_wait_range`: (0.5, 1) - 开仓时间间隔范围（分钟），随机选择
- `close_wait_range`: (10, 20) - 平仓时间间隔范围（分钟），随机选择  
- `max_wait_min`: 72 分钟 - 最大持仓时间，超过后强制平仓

**工作逻辑**:
- **开仓控制**: 在指定时间间隔后允许开仓，根据价格选择开仓方向
- **平仓控制**: 在指定时间后允许平仓，或强制平仓避免长时间持仓
- **历史追踪**: 记录持仓时长历史，提供统计分析

**具体功能**:
- **交易节奏控制**: 通过时间间隔限制避免过于频繁的开仓操作
- **持仓风险控制**: 设定最大持仓时间，防止长期持仓风险积累
- **随机化处理**: 开平仓时间随机选择，避免可预测的交易模式
- **历史数据分析**: 跟踪持仓时长分布，优化时间参数设置

**适用场景**: 
- **高频交易防护**: 在价差频繁变化的市场中控制交易频率
- **风险时间管控**: 限制单笔持仓的最大风险暴露时间
- **策略稳定性**: 为其他策略提供时间维度的约束条件

### 2. 价差策略 (SpreadStrategy)

- **优先级**: 10 (较低)  
- **功能**: 基于两个交易所价差进行自适应套利

**核心参数**:
- `current_spread_sample_count`: 10 - 价差采样次数，用于计算基准价差
- `profit_threshold`: 0.05 - 盈利阈值（5%），平仓时价差收敛目标

**工作逻辑**:
- **开仓判断**: 当前价差 > 基准价差时触发开仓
- **平仓判断**: 价差收敛至目标阈值以下时触发平仓
- **实时价格计算**: 
  - Primary交易所: 使用市场最优价格（BBO）
  - Lighter交易所: 基于订单簿深度计算指定数量的加权平均成交价
- **价格冲击量化**: 计算在Lighter执行市价单对价格的冲击百分比
- **自适应方向**: 
  - Lighter > Primary: 价差收敛策略（做空价差）
  - Primary > Lighter: 传统套利策略（做多价差）
- **动态成本控制**: 
  - 手续费: 两个交易所的实际费率
  - 滑点成本: 基于Lighter订单簿的真实滑点计算
  - 价格冲击: 大单对Lighter价格的冲击成本
  - 综合净价差: 总价差 - 总成本

**具体功能**:
- **动态价差监控**: 实时采样两个交易所价差，建立价差基准线
- **方向自适应**: 根据价差方向自动选择合适的套利策略
- **收益优化**: 基于价差收敛程度判断最佳平仓时机
- **Lighter订单簿深度计算**: 实时获取Lighter订单簿深度，计算指定交易量的真实成交价
- **价格冲击评估**: 根据订单簿流动性评估大单交易对价格的冲击程度
- **滑点精确预估**: 基于实际订单簿数据预估交易滑点，而非简单的价差计算
- **流动性风险控制**: 当Lighter流动性不足时自动调整交易规模或暂停交易
- **成本核算**: 综合考虑手续费、实际滑点、价格冲击等真实交易成本

**适用场景**: 
- **稳定价差套利**: 适用于价差相对稳定、有规律波动的币种对
- **主流币种交易**: 如 BTC、ETH 等流动性好的主流币种
- **价差扩大期**: 当两个交易所价差明显扩大时的套利机会
- **高流动性环境**: Lighter订单簿深度充足，价格冲击较小的市场条件
- **市场效率套利**: 利用不同交易所间的价格发现效率差异获利

### 3. 清算风险策略 (LiquidRiskStrategy)

- **优先级**: 100 (最高)
- **功能**: 实时监控清算风险，确保资金安全

**核心参数**:
- `risk_threshold`: 0.02 - 风险距离阈值（2%），价格距离清算线不能小于此值

**工作逻辑**:
- **风险检测**: 实时计算当前价格到清算价格的距离百分比
- **强制平仓**: 当风险距离 ≤ 2% 时立即触发平仓
- **双边监控**: 同时监控主交易所和 Lighter 的清算风险
- **持仓分析**: 根据持仓方向（long/short）判断清算方向

**具体功能**:
- **实时风险计算**: 持续监控当前价格与强平价的距离百分比
- **双边风险监控**: 同时监控主交易所和对冲交易所的清算风险
- **紧急平仓机制**: 风险超过阈值时立即执行平仓，优先级最高
- **风险预警系统**: 提前预警接近清算线的持仓状态

**适用场景**: 
- **高杠杆交易**: 5倍以上杠杆交易的必要安全机制
- **市场极端波动**: 如重大新闻、政策发布等引发的价格剧烈波动
- **资金管理**: 防止因清算导致的重大资金损失
- **风险控制**: 作为整个对冲系统的最后一道安全防线

### 4. 价格波动策略 (PriceVolatilityStrategy)

- **优先级**: 80 (较高)
- **功能**: 基于价格波动率控制交易时机

**核心参数**:
- `volatility_threshold`: 0.005 - 波动率阈值（0.5%）
  - BTC 推荐: 0.0005-0.0008 (0.05%-0.08%)
  - 山寨币推荐: 0.001-0.0015 (0.1%-0.15%)
- `sample_count_range`: (20, 40) - 波动率采样次数范围
- `cache_duration`: 300秒 - 波动率计算结果缓存时间

**工作逻辑**:
- **开仓控制**: 波动率 > 阈值时拒绝开仓（REJECT）
- **平仓触发**: 波动率 > 阈值时主动平仓（TRIGGER）
- **波动率计算**: 基于价格变化率标准差的综合波动率
- **数据共享**: 与其他策略共享采样数据，提高效率

**具体功能**:
- **波动率实时计算**: 基于价格变化率标准差计算综合波动率指标
- **缓存机制**: 避免重复计算，提高系统响应速度
- **阈值动态调整**: 根据不同币种特性设置个性化波动率阈值
- **数据共享优化**: 与其他策略共享采样数据，提升整体效率

**适用场景**: 
- **高波动期规避**: 在市场出现异常波动时暂停新开仓
- **MEME 币交易**: 适合波动性极强的 MEME 币种风险控制
- **新闻事件期**: 在重大新闻发布前后的高不确定性时期
- **流动性保护**: 在市场流动性不足导致价格异常波动时保护资金
- **策略配合**: 与价差策略配合，在高波动期优先平仓而非开仓

## 策略决策机制

### 优先级执行顺序

**开仓策略链** (按优先级从高到低执行):
1. **LiquidRiskStrategy (100)** - 安全检查
2. **PriceVolatilityStrategy (80)** - 波动率控制  
3. **TimingStrategy (20)** - 时间控制
4. **SpreadStrategy (10)** - 价差套利

**平仓策略链** (按优先级从高到低执行):
1. **LiquidRiskStrategy (100)** - 紧急平仓
2. **PriceVolatilityStrategy (80)** - 波动平仓
3. **TimingStrategy (20)** - 时间平仓
4. **SpreadStrategy (10)** - 价差平仓

### 决策结果类型

- **TRIGGER**: 立即触发，跳过后续策略检查
- **PASS**: 检查通过，继续执行下一个策略  
- **REJECT**: 拒绝执行，终止策略链，等待下一轮

### 策略组合逻辑

- **开仓**: 所有策略必须 PASS 或至少一个 TRIGGER 才能开仓
- **平仓**: 任何一个策略 TRIGGER 即立即平仓
- **重试**: 遇到 REJECT 将等待并重新执行整个策略链

### 策略协同工作机制

#### 实际工作流程示例

**场景1: 正常开仓流程**
1. **清算风险策略**: 检查当前资金使用率和潜在清算风险 → PASS
2. **价格波动策略**: 计算当前市场波动率，低于阈值 → PASS
3. **时间策略**: 检查距离上次交易时间，满足间隔要求 → PASS
4. **价差策略**: 发现有利价差机会 → TRIGGER
5. **结果**: 立即执行开仓，跳过后续检查

**场景2: 风险阻止开仓**
1. **清算风险策略**: 检测到接近清算线 → REJECT
2. **结果**: 立即停止开仓流程，等待风险降低

**场景3: 高波动期处理**
1. **清算风险策略**: 安全检查通过 → PASS
2. **价格波动策略**: 检测到异常高波动 → REJECT
3. **结果**: 暂停新开仓，保护现有资金

**场景4: 紧急平仓流程**
1. **清算风险策略**: 检测到清算风险过高 → TRIGGER
2. **结果**: 立即执行平仓，不经过其他策略检查

#### 优先级设计

- **100级(LiquidRisk)**: 资金安全优先级最高，任何情况下都不能损失本金
- **80级(PriceVolatility)**: 市场环境判断，避免在不利环境下交易
- **20级(Timing)**: 交易节奏控制，防止过度频繁操作
- **10级(Spread)**: 盈利机会捕获，在安全前提下寻求收益

## 使用方式

### 基本运行命令

所有参数与原有的 `hedge_mode.py` 保持一致，仅需调整执行入口为 `hedge_mode_v1.py`, 对冲策略的参数需要到具体的策略类代码中进行调整。

```bash
# EdgeX + Lighter 对冲
python hedge_mode_v1.py --exchange edgex --ticker BTC --size 0.05 --iter 20

# GRVT + Lighter 对冲  
python hedge_mode_v1.py --exchange grvt --ticker BTC --size 0.05 --iter 20
```

**策略参数调优** (需要修改源码):

**TimingStrategy 时间控制**:
```python
# hedge_v1/strategy/timing_strategy.py
self.open_wait_range = (0.5, 1)      # 开仓间隔(分钟) - 可调整为 (1, 3) 降低频率
self.close_wait_range = (10, 20)     # 平仓间隔(分钟) - 可调整为 (5, 15) 提高频率  
self.max_wait_min = 1.2 * 60         # 最大持仓(分钟) - 可调整为 0.5 * 60 缩短持仓
```

**SpreadStrategy 价差控制**:
```python  
# hedge_v1/strategy/spread_strategy.py
self.current_spread_sample_count = 10   # 采样次数 - 可调整为 5-20
self.profit_threshold = 0.05            # 盈利阈值 - 可调整为 0.02-0.1
```

**LiquidRiskStrategy 风险控制**:
```python
# hedge_v1/strategy/liquid_risk_strategy.py  
self.risk_threshold = 0.02              # 风险阈值 - 可调整为 0.01-0.05
```

**PriceVolatilityStrategy 波动率控制**:
```python
# hedge_v1/strategy/price_volatility_strategy.py
self.volatility_threshold = 0.005       # 波动率阈值 - 根据币种调整
self.sample_count_range = (20, 40)      # 采样范围 - 可调整为 (10, 30)
```

**不同币种参考参数**:

| 币种类型 | 波动率阈值 | 价差阈值 | 时间间隔 | 风险阈值 |
|---------|----------|---------|---------|---------|
| BTC/ETH | 0.0005-0.0008 | 0.02-0.05 | 长间隔 | 0.02 |
| 主流币 | 0.0008-0.0012 | 0.03-0.06 | 中间隔 | 0.025 |  
| 山寨币 | 0.0010-0.0015 | 0.05-0.1 | 短间隔 | 0.03 |
| MEME币 | 0.0015-0.0025 | 0.08-0.15 | 短间隔 | 0.05 |

## 监控指标

### Telegram 推送通知内容

**HedgeMonitor** 通过 Telegram 提供全面的实时监控推送，包含以下类型的通知信息：

#### 1. 系统状态通知

| 通知类型 | 触发时机 | 推送内容 |
|---------|---------|---------|
| **启动通知** | 系统启动时 | • 启动时间<br>• 交易数量配置<br>• 交易所组合<br>• 计划执行轮数 |
| **停止通知** | 系统停止时 | • 停止时间<br>• 最终持仓状态<br>• 本轮统计信息<br>• 总交易次数<br>• 总交易量<br>• 总收益和平均收益<br>• 平均收益率和磨损率 |
| **异常报告** | 系统错误时 | • 异常时间<br>• 错误信息详情<br>• 上下文信息 |

#### 2. 交易执行通知

| 通知类型 | 推送时机 | 核心信息 |
|---------|---------|---------|
| **开仓执行通知** | 每次开仓后 | • 开仓时间<br>• **Primary交易所**: 开仓方向、持仓数量、开仓价格<br>• **Lighter交易所**: 开仓方向、持仓数量、开仓价格<br>• 触发策略列表及详细信息 |
| **平仓执行通知** | 每次平仓后 | • 平仓时间<br>• **双边开平仓信息**（价格、数量、方向）<br>• **收益明细**：Primary PnL、Lighter PnL、总收益<br>• **手续费详情**：开仓费用、平仓费用<br>• **收益率分析**：总收益率、单边磨损率<br>• **当前持仓状态**<br>• 触发策略列表<br>• 持仓异常警告（如有） |

#### 3. 持仓状态监控

| 通知类型 | 推送频率 | 监控内容 |
|---------|---------|---------|
| **持仓状态报告** | 每30分钟<br>（仅在有持仓时） | **未开仓状态**：<br>• 策略触发状态<br>• 双边持仓数量<br>• 当前价差<br>• 双边市场价格<br><br>**已开仓状态**：<br>• 双边持仓详情<br>• 开仓价 vs 当前市价<br>• 当前价差变化<br>• 实时盈亏预估 |

#### 4. 详细收益分析

**平仓通知中的收益明细表**：

| 收益项目 | 计算方式 | 说明 |
|---------|---------|-----|
| **Primary 手续费** | `开仓价格×数量×费率` + `平仓价格×数量×费率` | 负费率表示返还 |
| **Primary PnL** | 根据开平仓价差计算，扣除手续费 | 真实API获取或价格计算 |
| **Lighter PnL** | 根据开平仓价差计算 | 真实API获取或价格计算 |
| **总收益** | Primary PnL + Lighter PnL | 双边对冲净收益 |
| **收益率** | 总收益 / 双边投入本金 × 100% | 基于20x杠杆计算本金 |
| **磨损率** | 总收益 / 单边交易量 × 100% | 衡量交易效率指标 |

#### 5. 策略触发信息

**每次开仓/平仓通知中包含的策略详情**：

- **策略名称**: 触发的具体策略（如 TimingStrategy、SpreadStrategy 等）
- **触发原因**: 每个策略的具体触发逻辑和判断依据
- **策略消息**: 策略执行过程中的详细状态信息
- **决策结果**: TRIGGER/PASS/REJECT 及相应的处理逻辑

#### 6. 风险预警机制

| 预警类型 | 触发条件 | 通知内容 |
|---------|---------|---------|
| **持仓异常警告** | 平仓后持仓非零 | 🚨 警告：平仓后持仓非零，请手动检查！ |
| **数据获取失败** | PnL API调用失败 | 使用价格差计算替代，标注数据来源 |
| **清算风险警告** | 触发LiquidRisk策略 | 紧急平仓通知和风险评估 |

### 实时监控能力

- **持仓状态**: 主交易所与 Lighter 的仓位对冲状态实时跟踪
- **价差变化**: 实时价差监控和盈亏预测，支持预警机制
- **策略触发**: 各策略的触发频率和成功率统计
- **风险等级**: 基于市场条件的实时风险评估和自动预警

### 统计分析功能

- **累计收益**: 总收益和收益率统计，支持历史数据追踪
- **磨损分析**: 交易成本和磨损率趋势分析
- **策略效果**: 各策略的盈亏贡献分析和效果评估
- **时间分布**: 不同时段的交易表现和统计指标
